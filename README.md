# DAO

The Dao De Jing, chapter by chapter, compiled into system-design rules for
coding agents, and tested: the same task is run with and without each
chapter's rules, and the outputs are compared. Not a meditation text. The
rules are short, imperative, and domain-neutral; the commentary that
justifies them is in Chinese.

把《道德经》逐章编译成给 coding agent 用的系统设计规则，并且测它：同一个任务，
带规则和不带规则各跑几次，对比产出。这不是心灵读物。规则块短、祈使、不绑定领域；
解释为什么的部分用中文写在章节里。

## 这不是什么

- 不是 Rick Rubin 与 Anthropic 的 *The Way of Code*。那是给人读的诗，这是给 agent 读的约束。
- 不是 SOLID 一类的教条清单。规则来自原文的切法，每条都要在评测里证明自己改变了产出。
- 不是"放弃思考的 vibe coding"。目标是让 agent 按人类架构师的审美写代码，而不是替人类审美。

## 仓库结构

仓库自己遵守第一章的规则：原始层只追加，派生层可以重建。

| 路径 | 层 | 内容 |
|---|---|---|
| `start-here.md` | 原始 | 起点，一次对话记录。不改 |
| `chapters/NN.md` | 派生 | 每章的中文解读：原文、概念表、逐句翻译、例子、推论、规则草稿 |
| `rules/NN.md` | 派生 | 每章编译出的英文规则块，直接放进 CLAUDE.md 或 system prompt |
| `eval/task.md` | 派生 | 评测任务。会随时间演化，旧版本在 git 历史里，报告记录所用的 commit |
| `eval/README.md` | 派生 | 评测方法、对比清单、修改纪律、未决问题 |
| `eval/runs/<date>/*/` | 原始 | 每次评测中 agent 的产出。只追加，不回头改 |
| `eval/runs/<date>/REPORT.md` | 派生 | 对该次产出的对比分析 |

## 怎么用

把 `rules/01.md` 的内容放进项目的 `CLAUDE.md`、`.cursorrules` 或等价文件。每章一个规则块，可以单独用，也可以叠加。规则块只给结论，不给理由；要理由去读 `chapters/`。

## 注意事项

**这里的每一个名都是非常名。** 第一章的切法是 2026 年 11 月 7 日、读到第四章之前的理解。后面的章节会带来新概念（比如第四章的原子操作、业务逻辑、编排三层），会反过来改第一章的措辞。这是预期的，不是错误。重切的时候，旧的切法和它的证据都在 git 历史与带日期的标注里，能指回去。守住的只有一条：原文和评测产出不动，其余都可以重建。

**规则措辞只在两个不同任务上都失效后才改。** 单个任务上的失效只在章节里记一句，带日期和任务名。例外是让规则更通用的修改（禁词清单变成原则），一轮即可。详见 `eval/README.md`。

**规则块必须短且不绑定领域。** 例子只能出现在章节里，不能出现在规则里，否则评测任务的答案就写进了考题。第一章 12 条约 30 行；再长就违背了第四章的"冲"。

**术语尚未给 agent 定义。** "原始层 / 派生层"在规则 9 到 12 里直接使用，agent 目前靠规则 8 的标签反推。计划写一个共享的 `rules/glossary.md`，用可重建性做判定：删掉后能从来源确定性重算的是派生，否则是原始；非确定性计算（如 LLM 抽取）的输出是"该计算发生过"这一原始事件。

**评测要隔离。** 跑评测的 agent 不能读仓库，否则 baseline 会被章节内容污染。baseline 在三次运行中几乎零偏差，所以单次 baseline 有代表性；treatment 的偏差只出现在规则没规定的地方，这是想要的。

**第 1 条会在需求缺规模时少建。** 任务没写规模，agent 就不建检索，并明说"未知"。这是规则在正确工作，但意味着给 agent 的请求要带上已知的规模。
